# 总体方案

## 1. 产品定位

Starter 不再是“调试页”，而是 Synra 的第一款能力展示插件：用少量真实动作让用户理解手机、电脑、宿主和插件之间如何协作，同时保留开发者可观察、可验证的参考实现。

## 2. 信息架构

主导航建议为：

```text
首页 | 演示 | 开发者 | 诊断 | 关于
```

### 首页

- 一句话解释 Synra；
- 展示设备协作、插件扩展、权限隔离三个核心概念；
- 直接引导进入演示；
- 不展示大量版本和内部字段。

### 演示

默认页面，顶部提供紧凑的目标电脑选择器，下面依次展示三张能力卡：

1. 让电脑打开链接；
2. 剪贴板；
3. 应用坞。

### 开发者

解释 manifest、Rust/Wasm headless、Vue 页面、宿主客户端和一次 action 调用链。当前插件页面本身作为示例代码的运行结果。

### 诊断

迁移当前诊断台：版本、宿主环境、运行诊断、耗时、错误码和最近请求记录。

### 关于

介绍 Synra、Starter、独立插件、文档和源码入口，并明确当前能力边界。

## 3. 设计原则

- 价值优先：首屏先讲用户能做什么，再讲内部实现；
- 真实结果：成功、拒绝、超时、离线和不支持都显示真实状态；
- 演示极简：每张卡只保留一个主要动作；
- 设备上下文共享：目标电脑只在演示页顶部选择一次；
- 权限就近说明：不单独做设备管理和权限管理 Tab，必要说明放在演示卡片内；
- 复杂业务外置：Touchpad 不复制到 Starter；
- 遵循主程序：复用主程序重构确立的层级、控件密度、触控规则、弹层和错误表达。
