# 视觉与交互规范

## 1. 参考来源

本次重构参考主程序界面流程重构形成的原则：

- 页面标题和正文建立清晰层级；
- 普通控件约 32px，紧凑控件约 28px；
- 低频解释和管理动作折叠或进入次级区域；
- 常用动作常显，单卡片只保留一个主要动作；
- 触控环境使用独立触控规则，不依赖窄屏宽度猜测；
- 错误、加载、空状态和成功状态分别表达；
- 不使用巨大空容器、诊断气泡或人为插入中文按钮空格；
- 组件承担局部状态，页面只负责组合流程。

## 2. 页面骨架

桌面端：

- 最大内容宽度约 960px；
- 页面标题、描述和导航固定在顶部；
- 演示卡片纵向排列，卡片之间使用稳定间距；
- 应用坞使用自适应网格；
- 不因状态消息出现而改变主要布局宽度。

移动端：

- 内容使用全宽安全边距；
- 链接输入和发送按钮在极窄屏幕下自动改为上下排列；
- 快捷链接按钮可横向滚动或换行；
- 应用图标保持足够触控尺寸；
- `any-pointer: coarse` 下使用更大的触控目标，而不是用 viewport 宽度替代。

## 3. 卡片状态

每张演示卡至少覆盖：

- 初始说明；
- 未选择目标；
- 正在加载/发送；
- 成功；
- 目标离线；
- 能力未授权或不支持；
- 超时；
- 可恢复失败。

错误信息应说明：发生了什么、是否已执行、用户下一步该做什么。禁止把失败渲染为“发送成功”。

## 4. 权限说明

不创建独立权限 Tab。演示卡底部提供轻量折叠说明：

- 本次演示需要哪些能力；
- 哪些能力已经可用；
- 权限如何影响当前按钮；
- 配对设备不等于拥有所有操作权限。

## 5. 主程序风格统一

- 优先使用现有 Synra 主题 token；
- 颜色、圆角、字体、按钮密度和焦点样式跟随主程序共享主题；
- 不引入新的 UI 框架；
- Starter 独立打包时保留可读的降级样式；
- 深色模式跟随宿主主题，不自行维护另一套主题语义。
